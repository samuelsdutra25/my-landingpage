# Samuel Dutra: portfolio landing page

A one-page portfolio for Samuel Dutra, a freelance front-end developer. The site builds trust with small clients and sends them to contact Samuel (through a contact form). He builds websites, online stores, dashboards and other front-end work.

The site itself is built with plain HTML, CSS and JavaScript plus Tailwind CSS. There is no framework and nothing to build on the server: a small Node script writes the text into the HTML before each commit, so `index.html` opens directly and every page has its content without JavaScript. Samuel also works with React, but a simple page like this one doesn't need it.

> **Status: MVP.** The layout, design system and behavior are done. The site copy is written (English and Portuguese), and the links, photo and project texts are placeholders. See [Before launch](#before-launch).

## What's inside

- **One page, eight parts:** header, hero, what you get, services, projects, how it works (four boxes joined by semicircles), about, and a final call to action with the footer.
- **English and Portuguese, each with its own address.** English at `/`, Portuguese at `/pt/`, so both can be found on Google. The EN/PT toggle in the header links the two pages and keeps the section you were reading.
- **A hero that measures itself.** A small wireframe builds itself, and under it the page shows how long it really took to be ready in the visitor's browser (from the Navigation Timing API). If the browser can't measure it, the line stays hidden.
- **Editable without touching the HTML.** Links, photo, projects and all text live in `main.js`; `npm run build` writes them into the pages.
- **Ready for search.** Title, description, canonical, `hreflang`, share previews and structured data are generated for each language, with `sitemap.xml` and `robots.txt`. See [SEO.md](SEO.md).
- **Accessible by default.** Semantic HTML, one `h1` and a correct heading order, a skip link, visible keyboard focus, labelled controls, and `prefers-reduced-motion` support.
- **Fast.** No libraries besides Tailwind's compiled CSS (about 30 KB), [GSAP](https://gsap.com) with its ScrollToPlugin for the button bounce and the smooth scroll (loaded from `assets/`) and one font hosted with the site (two files of 16 KB).

## Tech stack

| Part | Choice |
|---|---|
| Markup, behavior | HTML and vanilla JavaScript (no framework, no TypeScript) |
| Styling | [Tailwind CSS v4](https://tailwindcss.com) through its CLI, plus a small hand-written `style.css` |
| Font | [Hind](https://fonts.google.com/specimen/Hind), weights 400 and 700, hosted in `assets/fonts/` (SIL Open Font License) |
| Hosting | Cloudflare (Workers with static assets, free). Any static host works, but `.assetsignore` and `wrangler.jsonc` are Cloudflare's |

## Run it locally

To look at the site, open `index.html` in your browser. That's all. (The EN/PT links also work from the folder.)

To change text, links or styles, you need [Node.js](https://nodejs.org) (the project was set up with Node 24 LTS):

```bash
git clone git@github.com:samuelsdutra25/my-landingpage.git
cd my-landingpage
npm install
npm run watch      # rebuilds assets/tailwind.css while you edit styles
npm run build      # after editing main.js: writes the text into the pages
```

| Command | What it does |
|---|---|
| `npm run build` | Builds everything: the CSS, then the pages (`build:css` + `build:html`) |
| `npm run build:css` | Builds `assets/tailwind.css` once, minified |
| `npm run build:html` | Writes the text from `main.js` into `index.html`, `404.html` and their Portuguese copies in `pt/`, plus the `<head>` tags, `sitemap.xml` and `robots.txt` |
| `npm run watch` | Rebuilds the CSS every time you save |
| `npm run vendor:gsap` | Copies GSAP and its ScrollToPlugin from `node_modules` to `assets/` (only needed when updating GSAP) |

Run `npm run build` and commit the result before you push or deploy. If you forget, the live site won't have your new text or classes. Running it twice changes nothing, so it is always safe to run.

## Edit the content

Everything Samuel replaces is in [main.js](main.js). After editing it, run `npm run build` to see the change.

### `SITE`: links, photo, projects, stack

The top of the file. Search for `TODO` to find every value that still needs a real one.

```js
const SITE = {
  url: 'https://samueldutra.com.br/', // the address: canonical links, share previews, sitemap
  initials: 'SD',
  photo: '',                    // e.g. 'assets/samuel.jpg'
  links: { github: '#', linkedin: '#', instagram: '#', whatsapp: '#', email: 'mailto:hello@example.com' },
  stack: ['HTML', 'CSS', 'Tailwind', 'JavaScript', 'GSAP', 'React'], // chips in About
  form: { action: '' },         // contact form endpoint, see below
  scores: { performance: 100, accessibility: 100, seo: 100 },   // real Lighthouse scores of this page
  projects: [ { placeholder: true, image: '', url: '#', type: { en, pt }, title: { en, pt }, text: { en, pt },
                details: { about: { en, pt }, role: { en, pt }, stack: [] } }, /* ... */ ],
};
```

- `scores` are the Lighthouse numbers shown in "What you get". They must be real: run Lighthouse (Chrome DevTools, mobile) on the deployed site and paste the results. The rings and counters animate to whatever is here.
- `form.action` is where the contact form sends messages. Empty (the default): the form opens the visitor's email app with the message ready, using `links.email`. To receive messages without that step, create a form on a service such as Formspree or Basin, paste its URL here and the form will send in the background (it POSTs the fields and expects a JSON answer). Publish and test one message after changing it.
- Put images in `assets/` and point to them by path.
- Set `placeholder: false` on a project when it's real. That hides its "Example" badge.
- Only the first project card is in the HTML for now. The online store and dashboard cards are commented out in `index.html`; remove the comment markers to bring them back.
- A new technology in `stack` gets a sand chip. To give it its own pastel color, add it to `STACK_COLORS` in `scripts/build-html.mjs`.
- Real `https` links to LinkedIn, GitHub and Instagram also go into the structured data for Google (`sameAs`), and the photo becomes the person's `image`, on the next build.
- `type` is the short label shown on each project (website, online store, dashboard).
- `details` is what appears when a visitor clicks a card: an overview (`about`), what Samuel did (`role`) and the technologies used (`stack`). The card opens with a smooth animation.

### `TRANSLATIONS`: all the text

Every piece of text is a key in `TRANSLATIONS.en` and `TRANSLATIONS.pt`. In the HTML, an element names its key in `data-i18n`, and the build writes the text inside it (English in `index.html`, Portuguese in `pt/index.html`):

```html
<h2 data-i18n="services.title">Services</h2>
```

To add or change text, edit the key in **both** languages and run `npm run build`. To add a new text element, give it an empty `data-i18n` key in `index.html`, add the key to both objects and build. Never type text into the HTML: the next build overwrites it. The only text written directly in the HTML is the logo. `meta.title` and `meta.description` are what Google shows in its results.

The site copy is final, except the project texts, which live in `SITE.projects`.

### Opening animation

An ink panel with a welcome message ("Welcome" / "Seja bem-vindo", key `intro.welcome` in `TRANSLATIONS`) covers the page while a wide amber line (rounded, going past the word on both sides) is drawn under it, in the style of the lines in "How it works" (with a dot at its tip), and a number counts from 0 to 100% below it. The count holds at 90% until the page has finished loading (at most 4 s), then the panel lifts away. It plays once per visit (per browser tab), and is skipped with reduced motion or when the link points to a section (`#projects`). To see it again, open the site in a new tab or run `sessionStorage.clear()` in the console and reload. The code is `playIntro()` in `main.js`, the styles are under "Opening animation" in `style.css`, and the check that decides whether it plays is the small script in the `<head>` of `index.html`.

## Design system

Everything lives in the `@theme` block at the top of [src/input.css](src/input.css). Change a value there, rebuild, and it updates across the site.

| Token | Hex | Used for |
|---|---|---|
| `cream` | `#FEF3E2` | Page background, text on dark areas |
| `sand` | `#F2DFC0` | Contrast sections, kept subtle on purpose |
| `ink` | `#2A1A0E` | Main text, dark sections |
| `orange` | `#D4621A` | Primary buttons only |
| `amber` | `#F4AE52` | Accents on dark backgrounds, badges |

Transition tones in the same warm family fill the gaps: `linen`, `ink-soft`, `line`, `ink-raised`, `cream-muted`, `orange-deep`, `orange-hover`, and `score`, `score-ink` and `score-soft` for the Lighthouse rings. A few colors step outside the palette on purpose, each commented in `src/input.css`: the hero window dots, the green checks and label in "What you get", the pastel chips in About, and the brand colors of the contact icons on hover.

Type is Hind everywhere, with a scale defined as tokens (`display`, `title`, `heading`, `body`, `small`, `button`). The page uses two radii (10px for buttons and fields, 16px for tiles) and there is a single shadow, on the hero mock.

**Contrast note:** cream text on `orange` measures 3.44:1. That passes WCAG AA only as large text, so button labels are Hind bold at 1.2rem (about 19px) or larger. Don't shrink them. Orange is never used for small text on cream.

## Deploy

The site is static, so it needs no build on the host. It is published on **Cloudflare** (Workers with static assets, free plan).

- `wrangler.jsonc` tells Cloudflare to serve the project folder as the site. The Worker name in it (`samueldutra`) must match the name in the Cloudflare dashboard.
- `.assetsignore` lists what must **not** be published (README, CLAUDE.md, SEO.md, `src/`, `scripts/`, `.claude/`, `package.json`, `.git/`...). If you add a new internal file or folder to the project, add it there too, or it becomes public.
- Run `npm run build` and commit before you push, because the host does not build.

Steps (first time):

1. Put the repository on GitHub.
2. Cloudflare dashboard > **Workers & Pages** > **Create application** > connect **GitHub** and choose the repository.
3. Worker name: `samueldutra`. Leave the build command empty and keep the default deploy command (`npx wrangler deploy`). Save and deploy.
4. Open the `*.workers.dev` address and check the site, `/pt/`, and that `/CLAUDE.md` and `/README.md` return 404.
5. Domain: add `samueldutra.com.br` to Cloudflare (Free plan) and change the name servers at Registro.br to the two Cloudflare gives you. Wait until Cloudflare says the domain is active.
6. Worker > **Settings** > **Domains & Routes** > **Add** > **Custom Domain** > `samueldutra.com.br`.
7. Make `www` redirect to the plain domain: add a proxied DNS record for `www` and a Redirect Rule from `www.samueldutra.com.br` to `https://samueldutra.com.br` (301).
8. Turn off the `*.workers.dev` address and the preview URLs in the Worker's **Domains & Routes** settings, so Google sees only one copy of the site.

After this, every push to the main branch publishes by itself.
